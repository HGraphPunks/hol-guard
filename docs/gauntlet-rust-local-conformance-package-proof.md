# Rust local conformance package shadow proof

This is a read-only diagnostic over one **historical Python-produced** local conformance package. It does not run a control, authenticate physical effects, authorize candidate execution, or qualify a benchmark result. Final implementation source is commit `8fe4ffb4`; the static Linux ARM64 binary SHA-256 is `2bc8fa6afa0a3abe4609f591479aa9878672d0beb1b9b462daff25dce1ca1a6d`. The binary was installed Root:Root mode `0500`, one link, at `/opt/hol-gauntlet/gauntlet-local-conformance-shadow-2bc8fa6a` in the idle `hol-beta-bootstrap-20261016-004` VM.

Outside inputs to the Rust read were the v7 config canonical SHA-256 `e28d37d51438dfbd771e537579003693cb0aaace51a14f6f40c9e14feea410c1`, the historical Root-owned controller tree digest `bf2d2c7fd5d672209904cc29f3519a7500c1085df5fcf20cfbc9bff1b5057076`, and the config-pinned package SHA-256 `93d3bfd73301e9b095b41b856a7b208455c999ee2b83e0ecacaab0f19368d78d`. The config belongs to retained candidate source `76c31929833b5571d25a56d9783e24a0997d5422`, package version `3.49.0`; its package and config files are under `/opt/hol-gauntlet/candidates/76c31929833b5571d25a56d9783e24a0997d5422/`. The old controller generation is `/opt/hol-gauntlet/controller-8285b68c3198aec1`. These pins were observed on the same VM, not independently approved for production.

The Rust reader rechecks the complete controller tree, loads the outside-pinned config, hashes every declared file asset including conformance, then compares all 50 exact named execution-source files to the package. It matches the observed Linux platform and config-derived runtime tuple, written review fields and review-document digest, exact SDK/Bun package declarations, five canonical record digests, five signed controller openings and reported tails, and distinct session IDs. It recomputes five Native review summaries from signed event rows, including the cancel role's expected missing Post. It reads the controller tree and file assets again before returning. No Python candidate code is imported by Rust.

The SHA-matched binary returned five roles (`boundary`, `cancel`, `input-binding`, `success`, `timeout`), 50 source hashes, five distinct sessions, five recomputed review summaries, `public_inputs_verified:false`, `independent_kernel_sdk_effects_verified:false`, `qualification_eligible:false`, and `execution_eligible:false`. The historical Python `verify_local_conformance` on its matching old controller returned the same five roles and package digest with `trust_status:local-integrity-only` and `qualification_eligible:false`. Python was invoked with `-I -B` to avoid creating bytecode in the pinned controller.

Three read-only VM refusals were observed: a wrong config SHA refused before package opening; a wrong historical controller-tree SHA refused the complete tree; using the newer, otherwise matching controller generation `18d31910a8cefbd6` refused because execution-source bytes differ. Local tests also refuse a candidate-chosen runtime tuple, changed source hash, changed review document, duplicate JSON keys, wrong raw package SHA and an oversized package. The evidence crate test suite passed, and native plus Linux ARM64 warnings-denied Clippy and Rustfmt checks passed.

This proves the Rust diagnostic can consume a retained local package under exact config/controller pins. The existing `verify_control_reported_tail` still checks producer-reported fields, not independently observed SDK, Native, kernel, cleanup or effect evidence. The current source-matched patched candidate has **not** run fresh conformance through Rust, and the older package cannot be reused as its admission. Fresh signed controls, independent effect scoring and an independently reviewed controller/install source remain open checklist exits.
