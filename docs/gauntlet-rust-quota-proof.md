# Read-only provider-quota journal parity

The Python v1 provider quota is an operational token counter. Its config is bound to an outside SHA-256 digest, and its append-only events form a canonical JSON hash chain. The journal itself is not HMAC-signed. A separate outside allowance digest is required after an extension. This is accounting evidence; it is not a Guard verdict or permission to call a model.

The Rust `read_provider_quota_snapshot` reader checks a canonical private directory and its ancestry, single-link owner-only files, the Python `quota.lock` through a nonblocking shared `flock`, bounded config and journal bytes, duplicate-key-safe JSON, row sequence/previous hash/config binding, and the reserve/settle/uncertain/extension state transitions. It returns the Python-shaped status snapshot with `qualification_eligible: false`. It cannot create a quota, reserve tokens, append a row, reset the counter, or run inference.

The [fixture generator](../ci/gauntlet-rs/proofs/freeze_provider_quota_v1.py) checks the pinned baseline SHA-256 of `provider_quota.py` (`f9dae71c6caee2a5e2e5727010d247cb5424dbe1b55c7f472a5093e10a72815e`) and its canonical JSON dependency `json_data.py` (`5d7a9b3b350ac5a7c318f02af8916101551371459f487cc0e5abd037792f817e`), then uses that Python class to create synthetic private journals. It produced the versioned [fixture](../ci/gauntlet-rs/crates/gauntlet-evidence/tests/fixtures/python_provider_quota_v1.json) with SHA-256 `ef89cf30a0dbefb483e16015b82404131ac5071a1cbde089838dc4043003f17e`; repeated generation produced the same bytes. The five accepted snapshots cover empty, reserved, settled, extended, and extended-reserved states; a sixth accepted snapshot captures halted unknown usage. Nine refused cases cover interrupted append, blank and duplicate-key rows, wrong previous hash, overlapping reservation, wrong settlement, unknown event, wrong config pin and wrong allowance pin. Rust matches each accepted snapshot exactly and refuses each negative at its mapped reason stage.

The Rust test also rejects group-writable quota ancestry, an unsafe root mode, a contended writer lock, a hard-linked events file and a symlinked events file. On the idle `hol-beta-bootstrap-20261016-004` VM, the static ARM64 evidence test binary had SHA-256 `6ff15a15b9a1dcfd7be6a7e393ef5eb5b967c396689018bf6a0a66e73a08f8bf` on both host and guest. All 11 Linux unit tests passed unprivileged, including the two quota tests. The tests used only synthetic temporary journals and did not read a live quota or contact the model provider.

The read-only `verify_provider_quota_observations` helper now replays the same private journal and matches chronological Python-frozen snapshots against exact hash-chain prefixes. It requires an independently supplied final journal hash, rejects a changed counter, a reordered snapshot and a wrong final hash, and permits repeated observations of one unchanged prefix. The accepted synthetic sequence spans empty, reserved, settled, allowance-extended, extended-reserved and halted-uncertain states. A later SHA-256-matched static ARM64 test binary (`e25395abee00c69bfe094eb3209f6c355e364961019d56e7fa4622b64c86644b` on host and guest) passed all 17 evidence unit tests unprivileged on the same VM, including this historical-prefix test. This can support later authentication of retained controller before/after records, but it has not yet been wired to live VM evidence or a trusted outside final-hash anchor.

The remaining quota migration is a Rust-owned durable writer with exact reserve, settle, unknown-usage halt, extension authorization, crash recovery and Python/Rust interoperation proof. This reader must stay diagnostic until those behaviors and the model-backed acceptance path have independent evidence.
