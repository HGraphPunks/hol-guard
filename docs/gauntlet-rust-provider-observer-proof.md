# Rust fixed-route provider metadata observer

The Python runner's `observe_provider` reads only `/v1/models` and `/v1/benchmark-quota` through direct HTTP at the local model route, caps each body at 65,536 bytes and verifies the advertised model plus idle quota adapter against outside pins. The separate `gauntlet-provider-observer` crate adds a read-only Rust transport for those two GETs. The destination is hardcoded to `192.168.5.2` with only the previously frozen 8001/8002 ports. It neither follows redirects nor exposes an arbitrary URL, path or HTTP method. Its response parser bounds headers, decoded body and chunk count, refuses ambiguous framing, and feeds strictly decoded JSON into the existing pure model and provider-status checks.

Four local tests passed: the exact outbound GET bytes with content-length, chunked and close framing; refusal of redirects, ambiguous/oversized bodies and duplicate JSON keys; refusal of arbitrary destinations before network access; and validation of the pinned Python idle provider-status fixture with an independently supplied model ID and pins. These tests use in-memory HTTP streams; they are not a live provider test. The current host provider at `192.168.5.2:8001` was unreachable during the latest VM check. This observer produces only diagnostic metadata with `qualification_eligible: false`; it has no inference POST, quota reservation or provider-generation attestation.

Before live use, bind its outside pins to a reviewed host provider generation and private quota journal, then prove a real exact-token request and crash-safe Python/Rust handoff. Until then the Python benchmark remains authoritative.
