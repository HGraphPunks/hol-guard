# Host-bound release-tag candidate build proof

The first Rust host-bound build of the retained v3.48.0 release archive used one-use job `0cb455d5575dc542`. The source archive was 44,902,294 bytes with SHA-256 `5d3eeff80bedd07042a28ffdf5d0192500669b238384ca71f7a3f8631f9382be`, commit `3864097f2e4fe623e403c1a948d9882f34c78690`, and an archived `refs/tags/v3.48.0` that matched the live exact-tag recheck. Its Mac host pin was durable (SHA-256 `ba837d8153c26e94a38e4bff90c80d33c29aad8d0ec74ffefe0c34d34949537e`), and the guest wrote a pre-run anchor. The container exited 1 because the Rust runner supplied `local-3864097f2e4fe623e403c1a948d9882f34c78690` to `git clone --branch`; that ref does not exist in this release archive. The failed result SHA-256 was `020afecbbf5e5df0209709117a06018db6bdd36d419875a1abec18a446de535a`, with no export and all three cleanup checks true. This job was consumed and was not retried.

The fix carries an explicit source tag through a new v3 Mac build pin, v2 Root readiness response, v2 pre-run guest anchor and v3 terminal/result-reader schemas. The fixed Podman request sends `HOL_GUARD_RELEASE_TAG=v3.48.0` without `HOL_GUARD_LOCAL_VERSION` for a release; local-source jobs still send `local-<commit>` and a local version. The Mac and Root readers reject a mismatched or missing tag. Historical v2 local-source host pins and results remain readable through their exact earlier binary paths. The fixed read-only builder plan still restricts release refs to v3.48.0 and v3.49.0.
