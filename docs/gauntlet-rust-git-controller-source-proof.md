# Exact Git-object controller source diagnostic

The uninstalled `gauntlet-host-shadow-controller-git` reads one caller-supplied local Git commit with fixed, read-only `/usr/bin/git` plumbing. It requires a full 40-character commit object, enumerates every regular file under `ci/gauntlet` (and `ci/__init__.py` if present), rejects links and unexpected modes, then reads each blob by object ID. It SHA-256 checks every blob against the embedded 426-file integration map, rechecks the tree, and derives the Python-bootstrap controller install digest. File, blob and total-byte limits and a cumulative deadline bound the diagnostic. It performs no fetch, checkout, install, import, build or benchmark launch.

On 2026-10-20, commit `5a696f781336a7e2d1141c66d9c51e65f00a8ab3` yielded 426 matched Git source files totaling 3,918,402 bytes. The resulting 395 selected install files had controller tree digest `a62dd6dd884448f83f612c4895648577ea66e18c720942b3b7ca3a707894170e`, agreeing with the independently frozen Python installer calculation. An invocation against the older `b4efd8171b06d0e13cbe12a077c376ecdc891fd1` source commit refused with exit 2 because its tree lacks the integration changes. A separate temporary Git fixture accepted exact blob hashes and refused an altered outside SHA-256. Local host-state tests and full-workspace Clippy passed. The preceding pushed head `5a696f78` passed both isolated Ubuntu contracts and native ARM64 binary CI jobs; this new diagnostic still needs CI on its own committed head.

The expected map and executable currently come from this draft PR and host, respectively; neither is an independently reviewed execution anchor. This proves local Git objects match the proposed source map. A trusted base must approve the exact commit and installer generation, supply outside pins to the VM, verify the installed Root-owned controller tree, and bind that tree to a contained worker child before any benchmark can be eligible.
